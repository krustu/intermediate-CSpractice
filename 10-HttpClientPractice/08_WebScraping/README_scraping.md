
## 1. robots.txt

Текстовый файл в корне сайта (`https://сайт/robots.txt`), где владелец **просит** ботов не заходить в определённые разделы.

```
User-agent: *          # правила для всех клиентов
Disallow: /admin/      # адреса, начинающиеся с /admin/, закрыты
Allow: /admin/public   # исключение внутри запрета (побеждает более конкретное правило)
Crawl-delay: 10        # просьба делать паузу (не часть стандарта, учитывают не все)
Sitemap: https://example.com/sitemap.xml
```

- Правила работают **по началу пути**: `Disallow: /api/analytics/` не закрывает `/api/search/...`.
- Это **просьба, а не защита**: технически ничто не мешает его игнорировать, но соблюдать его это базовая норма. Игнорирование считается недобросовестным поведением.
- Файл меняется: после смены дизайна или структуры сайта его надо перепроверять.

## 2. Условия использования (ToS)

- Юридический документ, `robots.txt` его **не заменяет**.
- Многие сайты запрещают автоматический сбор данных.
- Обычные последствия: блокировка по IP или аккаунту; претензии бывают редко и чаще при больших объёмах или перепродаже данных.

## 3. Правила ответственного скрейпинга

1. Сначала проверь, нет ли **официального API**: он всегда лучше парсинга.
2. Прочитай `robots.txt` и условия использования.
3. **Представляйся честно**: `User-Agent` с названием приложения (`MyApp/1.0`).
4. **Не нагружай сайт**: паузы между запросами, лимит частоты, параллельно только между разными сайтами.
5. Уважай `429` и заголовок `Retry-After`; при временных ошибках повторяй с растущей паузой (exponential backoff).
6. **Не качай повторно** то, что уже есть: храни виденное, запрашивай только новое.
7. **Бери только нужное**: особенно не собирай персональные данные (телефоны, имена) без необходимости.
8. **Не обходи защиту**: капчи, блокировки, смену IP и маскировку под браузер. Если заблокировали, остановись.
9. Личное использование и публикация/перепродажа это разный уровень риска (авторские права на тексты и фото).

## 4. Как это выглядит в моём проекте (RealEstateAggregator)

- Между страницами одного сайта стоит пауза (`DelayBetweenPages` в `MonitoringService`); разные сайты опрашиваются параллельно.
- Уже виденные объявления хранятся в базе, повторно не обрабатываются.
- Проверка `robots.txt` на 2026-10-06: путь `/kupit-kvartiru` у house.kg не закрыт; у Lalafo закрыты только `/api/analytics/` и `/api/experiment/`, а используемый `/api/search/v3/ads/search` под запрет не попадает. Перепроверять после изменений на сайтах.
- Lalafo API внутреннее, не официальное: стабильность не гарантирована.
- Проверить, что `User-Agent` выставлен в общем `HttpClient`.
- Улучшение: сообщать в Telegram, если источник вернул 0 объявлений на первой странице (тихий сбой).

## 5. how to answer responsibly

**Вопрос: «Как ты делаешь парсинг ответственно?»**

rus: сначала смотрю, есть ли официальный API, читаю `robots.txt` и условия сайта. Представляюсь честным `User-Agent`, делаю паузы и ограничиваю частоту, не качаю повторно то, что уже есть, и собираю только нужные данные. Блокировки и защиту не обхожу.

eng:
> I check the site's robots.txt and terms first and prefer an official API if there is one. I identify my client with an honest User-Agent, rate-limit requests, avoid re-downloading data I already have, collect only what I need, and never bypass blocks or protections.



- *Обязателен ли robots.txt?* Технически нет, это просьба, а не защита. Но соблюдать его нормально, а игнорирование считается недобросовестным. Сам по себе он обычно не закон, а условия использования это отдельный документ.
- *Что делать, если сайт блокирует?* Остановиться, не обходить блокировку; поискать официальный API или связаться с владельцем.
- *Что делать при 429?* Остановиться, прочитать `Retry-After`, подождать; при повторных ошибках увеличивать паузу (exponential backoff, лучше с jitter).
- *Чем robots.txt отличается от ToS?* robots.txt просьба для ботов о том, куда не ходить; ToS юридические правила использования сайта.
