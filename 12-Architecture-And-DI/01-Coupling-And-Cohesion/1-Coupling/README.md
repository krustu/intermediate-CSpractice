# Coupling (связанность)

**Идея:** связанность показывает, сколько класс знает про чужие детали. Чем больше знает, тем легче ломается при изменениях в другом классе.

## Что я делал
Погода из строки `"Warsaw;12"`: сервис отдаёт данные, принтер их печатает.

- `Bad`: `WeatherReport` сам создавал `new WeatherService()`, читал его поле и резал строку через `Split`. Знал и класс, и формат.
- `Good`: формат строки знает только `WeatherService`. Он отдаёт готовую модель `WeatherInfo`, принтер работает только с ней.

## Главное
- Вопрос для проверки: **кто должен знать формат данных?** Тот, кто их выдаёт.
- Между слоями передаём простую модель данных (DTO), а не сырую строку и не чужие поля.
- Поля делаем приватными, снаружи видно только то, что нужно.

## Что осталось
`new WeatherService()` всё ещё в `Main`. Как убрать, разбираю в теме 2 (Dependency Inversion).
